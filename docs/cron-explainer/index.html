What problem does this solve?
A single timezone assumption can run a data import at the wrong hour. This tool calculates actual upcoming dates for standard five-field Unix cron schedules in either UTC or your device-local timezone, including day-of-month and day-of-week rules.

  
How to use it
Enter minute, hour, day of month, month and weekday. Examples: 0 9 * * 1 (Monday at 09:00), */15 9-17 * * 1-5 (weekday quarter-hours). Select UTC for most hosted schedulers if the service documents UTC, or local when your runtime uses local time.

  
Scope and limitations
Supports standard numeric Unix cron: asterisk, steps, lists and ranges. It does not accept Quartz seconds, ? or AWS EventBridge syntax. Preview searches up to 370 days; confirm your actual scheduler's timezone, DST interpretation and day-field semantics.

 

 
Common questions
Is this the same as AWS EventBridge or Quartz?
No. Those cron dialects use different numbers of fields and day-of-week rules. This is standard five-field Unix cron only.
What if both day-of-month and weekday are specified?
This tool follows the common Vixie crontab OR rule when both day fields are restricted; some schedulers use different behavior.
Are these guaranteed future executions?
No. They are matching calendar times. A paused server, disabled workflow, DST policy or scheduler configuration can prevent a job.
